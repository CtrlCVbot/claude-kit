# 04. 로드맵 — Phase 1 (PoC) → Phase 2 (부분 도입) → Phase 3 (전면)

> **한 문장 요약**: 3 단계 점진 도입. 각 단계마다 **Exit Criteria** 를 충족해야 다음 Phase 진입. 실패 시 이전 단계로 rollback 가능.
>
> **비유**: 새 요리 레시피를 도입할 때, 먼저 **한 끼 시범 요리 (PoC)** → 주 2회 시도 (부분) → 레귤러 메뉴 (전면). 각 단계에서 맛평가를 거쳐 다음 단계 결정.

## Phase 1 — PoC (1~2일)

### 목표
dash-preview Phase 4 를 **kit 변경 없이 문서만으로** Epic 구조로 운영해보고, 실제로 효과가 있는지 검증.

### 수행 작업

#### P1-A. Epic Brief 작성
- 위치: `.plans/epics/00-draft/EPIC-20260422-001/00-epic-brief.md`
- 내용: `01-계층-설계.md §3` 양식 기반
- 주제: "dash-preview Phase 4 — 사용자 피드백 10 이슈 반영"

#### P1-B. Children Features 작성
- 위치: `.plans/epics/00-draft/EPIC-20260422-001/01-children-features.md`
- 4 IDEA (Lane 1~4) 를 children 으로 명시
- 의존성 매트릭스 (§01 §4) 포함

#### P1-C. Epic Binding (4 IDEA)
- 각 IDEA 파일에 프론트매터 `epic: EPIC-20260422-001` 추가 (수동)
- `backlog.md` 에 `Epic` 컬럼 수동 추가 (4행만)

#### P1-D. 실제 실행 + 관찰
- `/plan-screen IDEA-20260422-00{1,2,3,4}` → 4 건 screening 병렬 진행
- 첫 Feature (예: IDEA-20260422-002 Mock data, 가장 RICE 높음) 를 active 로 승격
- **관찰 기록**: `06-poc-observations.md` 작성

### Exit Criteria (Phase 2 진입 전 충족)

| # | 기준 | 측정 방법 |
|---|---|---|
| 1 | Epic Brief + Children Features 문서 작성 완료 | 파일 존재 + 필수 섹션 충족 |
| 2 | 4 IDEA 모두 `epic: EPIC-...` 메타 부착 | grep 검증 |
| 3 | `/plan-screen` 을 통해 최소 2 IDEA 가 Go 판정 | screening-matrix.md |
| 4 | Epic 의 Children Features 문서 업데이트가 **실제로 유용** 했는지 주관 평가 | 1~5 점 (최소 3점) |
| 5 | 문서 drift 발생 시 탐지 가능 했는지 | 예: Children Features 수정 vs IDEA 파일 수정 일관성 |

**Fail Criteria** (Phase 1 실패 신호):
- Epic 문서 작성 부담이 Feature 작성 부담을 초과 (너무 무거움)
- Children Features 문서가 IDEA 행 복제만 되는 "뻔한" 문서
- 4 Lane 병렬 실행 리듬이 오히려 손상 (Epic 계층 관리가 방해)

### Phase 1 산출물


## Phase 2 — 부분 도입 (1~2주)

### 전제조건
- Phase 1 Exit Criteria 5/5 충족
- 사용자 승인 (PoC 효과 확인)

### 목표
claude-kit 에 Epic 관련 최소 도구 세트 구축. 신규 Feature 부터 Opt-in 적용.

### 수행 작업

#### P2-A. 신규 커맨드 2건 (우선 1건)
- `/plan-epic` (생성, 조회, 상태 전이) — **우선 구현**
- `/plan-epic-adopt` (소급 연결) — Phase 3 에서 도입도 OK

#### P2-B. skill 1건
- `plan-epic-workflow` (라이프사이클 + 상태 머신 + 템플릿)

#### P2-C. rule 1건 + 기존 rule 1건 변경
- 신규: `plan-epic-hierarchy.md` (계층 정의 + Opt-in 원칙 + 금지 사항)
- 변경: `plan-idea-management` (epic 파라미터 언급)

#### P2-D. 스키마 확장
- `backlog.md` epic 컬럼 추가 (기존 행 전부 "—" 채움)
- `archive/index.md` epic 컬럼 추가 (기존 행 전부 "—" 채움)

#### P2-E. 기존 커맨드 확장
- `/plan-idea` 에 `--epic` 파라미터 지원 (optional)
- `plan-idea-collector` 에이전트 프롬프트 확장

#### P2-F. 문서 템플릿 3건
- `epic-brief.md`
- `children-features.md`
- `epic-binding.md`

#### P2-G. hook 1건 (disable 기본)
- `plan-epic-integrity.js`
- `.claude/settings.json` 에서 기본 disable, 사용자가 활성화

### Exit Criteria (Phase 3 진입 전 충족)

| # | 기준 | 측정 방법 |
|---|---|---|
| 1 | `/plan-epic` 커맨드 동작 (생성/조회/상태전이) | 실제 실행 3회 이상 |
| 2 | 신규 Feature 최소 1건 Epic 과 함께 등록 | `backlog.md` epic 컬럼 확인 |
| 3 | 기존 Feature 에 대한 영향 0 | 기존 `/plan-idea` 사용자 회귀 없음 |
| 4 | Phase 1 PoC 문서가 Phase 2 도구로 재현 가능 | `/plan-epic show EPIC-...` 로 확인 |
| 5 | 안정 운영 3~6개월 (실 사용 축적) | 최소 3~4 Epic 운영 경험 |

**Rollback Criteria** (Phase 2 실패 → Phase 1 로 롤백):
- `/plan-epic` 사용자 경험이 `/plan-idea` 보다 번거로움 (30분 이상 작업 증가)
- Epic 문서 유지보수 비용이 실익 초과
- 신규 Feature 담당자가 Epic 생성 여부에 혼란

## Phase 3 — 전면 도입 (1~2개월)

### 전제조건
- Phase 2 Exit Criteria 5/5 충족
- 3~6개월 안정 운영 + 3~4 Epic 실 사용 경험
- 사용자 승인 (전면 도입 결정)

### 목표
Epic 을 kit 파이프라인의 **정식 1단계** 로 승격. 기존 archive 의 제품 라인을 선택적으로 Epic 에 소급 연결.

### 수행 작업

#### P3-A. `/plan-epic-adopt` 커맨드 구현
- 02-마이그레이션-규칙 §2 시나리오 B (active) + C (archived) 지원
- 자동 검증: epic-binding.md 와 children-features.md cross-reference

#### P3-B. archived Feature 소급 Epic 연결 (선택적)
- EPIC-20260422-099 "OPTIC Landing legacy" 생성 (archived 상태)
- OLP / DASH / DASH3 를 소급 연결
- `archive/index.md` epic 컬럼 채움

#### P3-C. plan-epic-integrity.js hook enable
- `.claude/settings.json` 에서 기본 enable 로 승격
- 사용자가 disable 가능 (문서 명시)

#### P3-D. kit 공식 문서 업데이트
- `plan-pipeline.md` — 파이프라인 다이어그램에 Epic 단계 추가
- `CLAUDE.md` (프로젝트) — Epic 개념 소개
- `src/claude/core/rules/copy-commands.md` 에 Epic 컨텍스트 언급

#### P3-E. 에이전트 프롬프트 확장 (§03 §10 표)
- plan-prd-writer: Epic 컨텍스트 참조
- plan-bridge-writer: Bridge 에 Epic 링크 포함
- plan-reviewer: Epic 레벨 일관성 검증
- dev-architect: Feature 간 아키텍처 일관성 (Epic 범위)

### Exit Criteria (전면 도입 완료)

| # | 기준 | 측정 방법 |
|---|---|---|
| 1 | `/plan-epic-adopt` 동작 (active + archived 시나리오) | 실제 2회 이상 실행 |
| 2 | legacy archive 소급 연결 (OPTIC Landing 3 Feature) | EPIC-20260422-099 완성 |
| 3 | hook 활성화 상태에서 회귀 0 | plan-epic-integrity.js 경고 0건 |
| 4 | kit 문서 업데이트 완료 | plan-pipeline.md / CLAUDE.md / copy-commands.md |
| 5 | 사용자 설문 (선택) | Epic 도입이 실제로 도움이 되는지 주관 평가 (최소 4/5) |

## 완료 판정 방식 (각 Phase 공통)

각 Phase 종료 시:
1. Exit Criteria 체크리스트 문서화 (각 항목 pass/fail + 증거)
2. 사용자 승인 (명시적 "Phase N 완료" 선언)
3. 다음 Phase 착수 또는 rollback 결정
