기획 파이프라인 상세 지도

이 문서는 /plan-* 명령을 실제 실행 단위로 설명하는 상세 문서 패키지의 시작점입니다. 각 명령은 실행 목적, 호출되는 agents와 skills, hooks와 instruction rules, 생성·수정·이동되는 산출물, Claude/Codex 차이를 함께 다룹니다.

/plan-epic 포함

Epic은 여러 Feature를 묶는 상위 기획 단위입니다. 기존 flat flow와 호환되는 opt-in 기능이지만, 상세 가이드에서는 planning pipeline의 1급 항목으로 다룹니다.

상세 페이지

현재 상세 페이지는 idea intake, Epic 계층, screening, draft, PRD 작성, wireframe, design/stitch 분기, bridge, review, revise, archive, improve까지 이어지는 planning 핵심 흐름을 다룹니다. 각 페이지는 동일한 Claude/Codex 탭과 output lifecycle 구조를 사용합니다.

상세 보기

기획 파이프라인 맵

기본 흐름은 아이디어에서 시작해 PRD, wireframe, design 또는 stitch, bridge로 이어집니다. Epic은 필요할 때 상위 컨테이너로 켜는 opt-in 경로입니다.

0/plan-epic

선택 사항. 여러 Feature를 묶는 상위 목적, 성공 지표, Phase를 관리합니다.

1/plan-idea

아이디어를 .plans/ideas/00-inbox/에 등록하고 필요 시 Epic에 연결합니다.

2/plan-screen

RICE 또는 5축 평가로 Go/Hold/Kill을 판정하고 folder transition을 수행합니다.

3/plan-draft

First Pass와 draft brief를 만들고 Lite/Standard 경로를 정합니다.

4/plan-prd

승인 가능한 PRD를 작성합니다.

R/plan-review

주요 게이트마다 품질과 PCC 일관성을 검증합니다.

R2/plan-revise

리뷰나 사용자 피드백에 따른 기존 산출물 수정을 처리합니다.

5/plan-wireframe

요구사항과 화면 구조를 연결합니다.

6A/plan-design

Claude Code Design용 wireframe/high fidelity 프롬프트를 생성합니다.

6B/plan-stitch

Google Stitch 선택 경로 또는 통합 검증 보강 경로입니다.

7/plan-bridge

개발자가 실행할 수 있는 Feature Package로 넘깁니다.

8/plan-archive

완료된 산출물을 archive bundle로 정리합니다.

9/plan-improve

아카이브된 기능의 개선 요청을 등록하고 재진입 지점을 추천합니다.

각 단계가 어떤 파일을 생성하고 어디로 이동시키는지는 산출물 lifecycle에서 전체 경로 기준으로 확인합니다.

디자인 분기 기준

경로 언제 쓰나 다음 단계
/plan-design Claude Code Design을 사용해 2단계 프롬프트와 design manifest가 필요할 때 /plan-bridge
/plan-stitch Google Stitch 또는 PRD/Wireframe 통합 검증을 선택적으로 보강할 때 /plan-bridge
/plan-design -> /plan-stitch Claude Design 산출물을 만든 뒤 Stitch로 통합 보강이 필요할 때 순차 실행 사유 기록 후 /plan-bridge

상세 페이지 표준

각 command 상세 페이지는 같은 형식을 따른다. 사용자는 command마다 다른 문서 구조를 새로 배울 필요가 없습니다.

섹션 설명
Overview목적, 선행 조건, 다음 단계
Claude / Codex 탭각 runtime이 같은 기능 identity를 어떻게 소비하는지 비교
Runtime Flowcommand 실행부터 agent spawn, skill/rule 참조, hook guard, output 생성까지
Output Lifecycle생성, 수정, 이동, archive 대상 파일과 폴더
Rules and Guardsinstruction rule, hook guard, validation gate
Failure Modes중단 조건, 거부 조건, 수동 확인 조건
Lifecycle reference산출물 생성·이동·archive 경로를 공통 참조로 둔다.
Function referenceagents, skills, hooks, rules 색인을 공통 참조로 둔다.
