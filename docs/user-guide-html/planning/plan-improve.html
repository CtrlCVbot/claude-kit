Runtime Flow

  1. archive 로드

    .plans/archive/{slug}/ARCHIVE-{KEY}.md를 읽어 전체 맥락을 확보합니다.

  2. 개선 요청 등록

    카테고리, 우선순위, 상세 설명을 받아 IMP 문서를 만듭니다.

  3. 영향도 분석

    UI, 데이터, API, 성능, 접근성 영향도를 평가합니다.

  4. 재진입 추천

    변경 규모에 따라 Dev only, P7, P5, P3, P1 중 하나를 추천합니다.

  5. 승인 확인

    execute는 IMP가 approved 상태일 때만 진행합니다.

  6. 이력 갱신

    완료 후 IMP 상태와 ARCHIVE 개선 이력을 업데이트합니다.

Rules and Guards

Archive firstactive feature가 아니라 archive bundle을 기준으로 개선을 등록합니다.
Approval gateexecute는 approved IMP만 진행합니다.
Re-entry discipline변경 규모가 크면 기존 파일을 바로 고치지 않고 planning 단계로 재진입합니다.

Failure Modes

  • archive bundle이 없으면 먼저 /plan-archive를 안내합니다.
  • 승인되지 않은 IMP를 execute하려 하면 중단합니다.
  • 근본적 재설계는 기존 archive 수정이 아니라 새 /plan-idea 진입으로 분리합니다.

Next Step

개선 요청이 경량이면 개발로 이동하고, 재기획이 필요하면 /plan-draft, /plan-wireframe, /plan-bridge 중 추천 단계로 돌아갑니다.
