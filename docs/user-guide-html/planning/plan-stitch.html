/plan-stitch

/plan-stitch는 Google Stitch 활용 또는 PRD/Wireframe 통합 검증을 선택적으로 보강하는 경로입니다. 기본적으로 /plan-design과 택일하지만, 필요하면 순차 실행 사유를 남기고 둘 다 사용할 수 있습니다.

실행 예시

/plan-stitch {slug}
/plan-stitch {slug} --force-sequential --sequential-reason "이유"

Runtime Flow

  1. 입력 검증

    routing metadata와 wireframe 디렉터리 존재를 확인합니다.

  2. 배타 게이트 확인

    post_wireframe_path가 design이면 순차 실행 플래그가 필요합니다.

  3. 산출물 로드

    승인 PRD와 wireframe 산출물을 함께 읽습니다.

  4. agent spawn

    plan-stitch-integrator가 PRD와 화면 간 일관성을 검증합니다.

  5. 매핑 생성

    REQ-ID와 Screen-ID 매핑, 누락 탐지, 통합 컨텍스트를 생성합니다.

  6. PCC-05

    wireframe 레이아웃이 통합에 반영되었는지 확인합니다.

Rules and Guards

Wireframe requiredwireframe 없이 호출하면 중단합니다.
Sequential reason/plan-design 이후 실행하려면 --force-sequential과 사유가 필요합니다.
PCC-05PRD와 wireframe 통합 결과가 Feature Package 입력으로 충분한지 확인합니다.

Failure Modes

  • wireframe 디렉터리가 없으면 /plan-wireframe 선행을 안내합니다.
  • post_wireframe_path가 design인데 순차 실행 사유가 없으면 중단합니다.
  • REQ-ID와 Screen-ID 매핑이 불충분하면 validation.md에서 수정 대상으로 남깁니다.

Next Step

통합 산출물이 준비되면 /plan-bridge {slug}로 개발 handoff를 준비합니다.
