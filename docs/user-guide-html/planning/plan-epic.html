/plan-epic

/plan-epic은 여러 Feature를 하나의 상위 목적과 phase roadmap으로 묶는 opt-in 계층 관리 명령입니다. Epic 없이도 기존 flat planning flow는 그대로 동작하지만, cross-cutting 목표나 다중 Feature 묶음에는 Epic이 더 안전한 기준점이 됩니다.

Primary skillplan-epic-workflow
Main ruleplan-epic-hierarchy
Main hookplan-epic-integrity
Primary output.plans/epics/**

실행 예시

/plan-epic
/plan-epic "OPTIC Landing 제품 라인"
/plan-epic list
/plan-epic list --status=active
/plan-epic show EPIC-20260422-001
/plan-epic show EPIC-20260422-001 --verbose
/plan-epic advance EPIC-20260422-001 --to=planning
/plan-epic advance EPIC-20260422-001 --to=active
/plan-epic archive EPIC-20260422-001
/plan-epic phase generate --phase=B --features=F2,F4

Epic은 opt-in입니다. Feature가 2개 미만이거나 상위 목표가 불명확하면 독립 Feature flow를 쓰는 편이 낫습니다.

Runtime Flow

  1. Activation 기준 검증

    Epic이 필요한 규모인지 확인합니다. 기준 미충족 시 독립 Feature를 권장하고 생성하지 않습니다.

  2. ID와 디렉터리 생성

    EPIC-{YYYYMMDD}-{NNN} ID를 만들고 .plans/epics/00-draft/EPIC-.../를 생성합니다.

  3. Epic Brief 작성

    plan-epic-workflow 템플릿을 기준으로 목적, 성공 지표, 범위를 채웁니다.

  4. Children Features 연결

    자식 Feature가 결정되어 있으면 01-children-features.md를 만들고 binding을 기록합니다.

  5. 상태 전이

    draft -> planning -> active -> completed -> archived 순방향만 허용합니다.

  6. 링크 재작성

    상태 이동 시 Epic 경로가 바뀌면 관련 .plans/**/*.md 링크를 재작성합니다.

Rules and Guards

자산 역할
plan-epic-hierarchyEpic/Feature/Task 3단 계층, activation 기준, 상태 전이 gate의 SSOT입니다.
plan-epic-integrityEpic과 Feature binding cross-reference를 검증합니다. 기본은 FLAG 성격으로 문서화합니다.
agent-file-ownershipEpic 파일 편집 권한과 agent race를 방지하는 보조 규칙입니다.
dry-run-mode상태 전이 또는 생성 전 예상 변경을 확인할 때 사용합니다.

Failure Modes

  • Feature가 2개 미만이면 Epic 생성은 over-engineering으로 거부될 수 있습니다.
  • 상태 전이는 순방향만 허용합니다. 역방향 이동은 기본적으로 차단합니다.
  • 자식 Feature가 없으면 draft -> planning gate를 통과할 수 없습니다.
  • 승인된 자식 Feature가 없으면 planning -> active gate를 통과할 수 없습니다.
  • 모든 자식 Feature가 archived가 아니면 completed/archive 전이가 거부됩니다.
  • Codex authoring source가 없으므로 Codex 상세 구현은 manual-review 상태로 다뤄야 합니다.

Next Step

Epic을 생성한 뒤에는 /plan-idea "..." --epic=EPIC-...으로 자식 IDEA를 연결합니다. 기존 Feature를 소급 연결하는 명령은 현재 상세 패키지의 후속 문서에서 별도 gap으로 추적합니다.
