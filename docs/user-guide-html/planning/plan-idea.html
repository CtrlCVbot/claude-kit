/plan-idea

/plan-idea는 사용자의 아이디어를 구조화해 .plans/ideas/00-inbox/IDEA-{YYYYMMDD}-{NNN}.md 파일로 등록하고, backlog index와 다음 screening 흐름으로 연결하는 planning entrypoint입니다.

Primary agentplan-idea-collector
Main skillplan-idea-management
Primary output.plans/ideas/00-inbox/IDEA-*.md
Next command/plan-screen IDEA-...

실행 예시

/plan-idea
/plan-idea "검색 기능 개선"
/plan-idea list
/plan-idea IDEA-20260325-001
/plan-idea list --status=new
/plan-idea list --folder=00-inbox
/plan-idea "검색 기능 개선" --epic=EPIC-20260422-001
/plan-idea "검색 기능 개선" --dry-run

--epic은 Epic을 쓰는 프로젝트에서만 필요한 opt-in 연결입니다. --dry-run은 파일 변경 없이 생성될 결과와 검증 내용을 미리 보는 경로입니다.

Runtime Flow

  1. 입력 분석

    사용자 입력이 등록, 목록 조회, 상세 조회 중 무엇인지 판별합니다.

  2. 등록 시 agent spawn

    plan-idea-collector가 자연어를 구조화된 idea 문서로 변환합니다.

  3. 중복과 카테고리 판단

    feature, improvement, fix, research 분류와 기존 아이디어 유사도를 확인합니다.

  4. ID 채번

    IDEA-{YYYYMMDD}-{NNN} 형식으로 당일 순번을 부여합니다.

  5. 파일 생성과 index 갱신

    idea 파일을 만들고 backlog.md에 위치를 반영합니다.

  6. 다음 단계 안내

    /plan-screen IDEA-...로 screening 흐름을 안내합니다.

Rules and Guards

자산 역할
plan-idea-move-guard.plans/ideas/ 내부 허용된 folder transition만 통과시킵니다.
dry-run-mode파일 변경 없이 예상 생성 결과를 보여주는 공통 규칙입니다.
plan-epic-hierarchy--epic 사용 시 Epic/Feature 계층 규칙을 적용합니다.

Failure Modes

  • 중복 아이디어로 판단되면 새 파일 생성 전에 유사 항목을 먼저 보고해야 합니다.
  • --epic으로 지정한 Epic ID가 없으면 Epic 연결은 중단되어야 합니다.
  • --dry-run에서는 Write를 수행하지 않고 예상 결과만 출력해야 합니다.
  • idea folder를 임의로 이동하면 guard hook 또는 index drift가 발생할 수 있습니다.

Next Step

등록된 아이디어는 기본적으로 /plan-screen IDEA-{YYYYMMDD}-{NNN}로 이어집니다. Epic 기반 프로젝트라면 먼저 /plan-epic으로 상위 구조를 만들고 --epic으로 연결하는 흐름도 가능합니다.
