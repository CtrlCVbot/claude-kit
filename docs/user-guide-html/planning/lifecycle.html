기획 산출물 Lifecycle

이 페이지는 /plan-* 명령이 만드는 파일과 폴더를 한곳에 모은 reference입니다. 상세 command 페이지를 읽기 전에 전체 경로를 파악하거나, 산출물이 어디로 이동해야 하는지 확인할 때 사용합니다.

핵심 원칙

산출물은 pipeline 단계에 따라 생성, 승인, 보정, archive됩니다. 이미 archive된 원본은 직접 수정하지 않고 /plan-improve로 개선 요청을 새로 등록합니다.

빠른 경로표

영역 대표 경로 소유 단계 역할

명령별 산출물

0/plan-epic

.plans/epics/00-draft/EPIC-*/00-epic-brief.md, 01-children-features.md, .plans/epics/index.md를 생성하거나 갱신합니다.

1/plan-idea

.plans/ideas/00-inbox/IDEA-*.md와 .plans/ideas/backlog.md를 갱신합니다.

2/plan-screen

SCREENING-*.md와 screening-matrix.md를 만들고, 승인 시 IDEA를 20-approved로 이동합니다.

3/plan-draft

Lite는 active 단일 문서로, Standard는 drafts/{slug}/first-pass.md와 routing metadata로 분기합니다.

4/plan-prd

00-draft/{slug}-prd.md를 작성하고 승인되면 10-approved/{slug}-prd.md로 승격합니다.

5/plan-wireframe

.plans/wireframes/{slug}/ 아래 화면 구조, navigation, component specification을 저장합니다.

6A/plan-design

prompt-01-wireframe.md, prompt-02-highfidelity.md, manifest.md를 .plans/design/{slug}/에 둡니다.

6B/plan-stitch

.plans/stitch/{slug}/에 PRD/Wireframe 매핑과 통합 검증 결과를 저장합니다.

7/plan-bridge

.plans/features/active/{slug}/00-context/에 개발 handoff context와 architecture binding을 정리합니다.

8/plan-archive

ARCHIVE-{KEY}.md, sources/, improvements/를 만들고 index를 갱신합니다.

이동 규칙

상황이동주의
Idea 승인00-inbox 또는 10-screening → 20-approved사용자 승인 없이 자동 승격하지 않습니다.
PRD 승인.plans/prd/00-draft/ → .plans/prd/10-approved/wireframe 진입 전 승인 상태를 확인합니다.
Epic 상태 전이.plans/epics/{prev}/EPIC-*/ → {next}/EPIC-*/tracked면 git mv, untracked면 일반 이동을 사용합니다.
Feature 완료active 산출물 → .plans/archive/{slug}/sources/원본 보존을 위해 archive bundle과 sources를 함께 둡니다.
Archive 이후 개선원본 수정 없음. improvements/IMP-*.md 생성archive 원본은 불변으로 봅니다.

리뷰와 수정

/plan-review는 read-only 검토가 기본입니다. 산출물을 직접 고치지 않고, 보정이 필요하면 /plan-revise로 넘깁니다. /plan-revise는 기존 파일만 수정하며 새 산출물을 만들지 않습니다.

대상수정 방식담당 writer
.plans/ideas/**/IDEA-*.md기존 IDEA section 보정plan-idea-collector
.plans/ideas/**/SCREENING-*.md평가 근거 보정plan-idea-screener
.plans/features/drafts/**draft/first-pass 보정plan-draft-writer
.plans/prd/10-approved/**승인 PRD 보정plan-prd-writer
.plans/wireframes/**화면 구조 보정plan-wireframe-designer
.plans/archive/**직접 수정 금지/plan-improve로 전환

Archive 구조

.plans/archive/{slug}/
├── ARCHIVE-{KEY}.md
├── sources/
│   ├── ideas/
│   ├── prd/
│   ├── wireframes/
│   ├── design/
│   ├── stitch/
│   └── feature-context/
└── improvements/
    └── IMP-{KEY}-{NNN}.md

archive는 완료 시점의 증거 묶음입니다. 완료 후 개선 요청은 improvements/에 새 문서로 기록하고, 원본을 직접 수정하지 않습니다.

Codex 기준

Codex 탭은 같은 lifecycle을 다른 runtime surface로 설명합니다. 사용자 실행 절차는 주로 .agents/skills/**와 .codex/agents/*.toml을 기준으로 읽고, 일반 지침은 AGENTS.md가 보조합니다.

Claude 개념Codex에서 보는 기준예시
Command workflowSkill 중심 workflowplan-revise-workflow, plan-archive-workflow
Writer agentSubagent.codex/agents/plan-prd-writer.toml
Instruction ruleAGENTS.md guidance 또는 skill 내부 guardrailcheckpoint-policy, writer-output-format
Hook guard지원 여부를 별도 확인문서 guard, review trigger, archive guard

실행 전 체크리스트

  • 지금 산출물이 어느 stage 폴더에 있는지 확인합니다.
  • 새 파일 생성인지, 기존 파일 수정인지, archive 이후 개선 요청인지 구분합니다.
  • 승인 또는 상태 전이에는 사용자 확인이 필요한지 확인합니다.
  • archive 내부 원본을 수정하려는 경우 즉시 멈추고 /plan-improve로 전환합니다.
  • Codex에서는 관련 skill과 subagent를 먼저 확인하고, plugin output을 source of truth로 보지 않습니다.
