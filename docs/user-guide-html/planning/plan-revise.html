/plan-revise

/plan-revise는 이미 만들어진 기획 산출물에 사용자 수정 요청을 반영하는 표준 수정 프로토콜입니다. 새 파일을 만드는 명령이 아니라, 기존 artifact를 안전하게 읽고 필요한 섹션만 수정합니다.

Primary agent경로 패턴으로 자동 추론
Main rulecheckpoint-policy.md §8
Primary output수정된 기존 파일
Codex statusskill-centered workflow skill + subagent 중심

실행 예시

/plan-revise {artifact-path} "수정 지시"
/plan-revise .plans/prd/10-approved/hero-refresh-prd.md "결정 포인트 근거 확장"
/plan-revise .plans/wireframes/hero-refresh/screens.md "모바일 빈 상태 화면 추가"

Runtime Flow

  1. workflow skill 진입

    Codex에서는 plan-revise-workflow skill이 절차, guardrail, subagent 선택의 기준이 됩니다.

  2. 경로 검증

    대상 파일 존재 여부와 archive 내부 파일 여부를 확인합니다.

  3. subagent 추론

    파일 경로 패턴으로 plan-prd-writer, plan-bridge-writer 같은 재호출 대상을 고릅니다.

  4. 수정 prompt 생성

    이전 산출물, 사용자 요청, 보존할 섹션, 수정할 섹션을 구조화합니다.

  5. writer 재호출

    선택된 agent가 기존 파일을 읽고 필요한 섹션만 수정합니다.

  6. 변경 이력 기록

    수정된 파일의 변경 이력 섹션에 요청 반영 row를 남깁니다.

  7. 재검증 안내

    필요하면 /plan-review로 변경 산출물을 다시 검토합니다.

Rules and Guards

Archive immutable.plans/archive/**/*.md는 원본 불변 원칙에 따라 수정하지 않습니다.
No new file새 artifact가 필요하면 원본 생성 command를 다시 사용합니다.
Critical checkpointcritical checkpoint는 일반 수정으로 우회하지 않습니다.
Epic ownershipEpic 전용 소유 파일은 메인 흐름에서만 수정합니다.

Failure Modes

  • 대상 파일이 없으면 HARD FAIL로 중단합니다.
  • archive 내부 파일이면 수정하지 않고 개선 요청 또는 새 파이프라인 진입을 안내합니다.
  • 경로 패턴으로 agent를 추론할 수 없으면 사용자에게 담당 agent 명시를 요청합니다.
  • Codex에서는 plan-revise-workflow가 경로로 subagent를 고르되, 애매한 경로는 담당 subagent를 사용자에게 확인합니다.

Next Step
