/plan-archive

/plan-archive는 완료된 기능의 기획과 개발 산출물을 archive bundle로 묶고, 원본 파일을 sources/로 이동해 이후 개선 요청의 기준점을 만듭니다.

/plan-archive list

/plan-archive status
/plan-archive {slug} --feature F{N}

Runtime Flow

  1. 완료 검증

    Lite 또는 Standard pipeline과 Dev 완료 상태를 확인합니다.

  2. 소스 수집

    ideas, features, PRD, wireframes, stitch, bridge 산출물을 slug 기준으로 찾습니다.

  3. 사용자 확인

    이동할 파일 목록과 archive 대상 범위를 보여주고 확인을 받습니다.

  4. archive 구조 생성

    .plans/archive/{slug}/sources/와 improvements/를 준비합니다.

  5. 원본 이동

    git mv로 원본 파일을 sources/ 아래로 옮깁니다.

  6. 번들 생성

    ARCHIVE-{KEY}.md에 산출물 내용을 인라인합니다.

  7. 인덱스 갱신

    archive/index.md, backlog, screening matrix를 archive 경로로 갱신합니다.

Rules and Guards

Pipeline completeLite는 P1, P2, P3, P5, P7, Dev 완료가 필요합니다. Standard는 P1부터 P7과 Dev 완료가 필요합니다.
Source preservation원본 삭제가 아니라 sources/ 이동으로 history를 보존합니다.
Single bundle사용자가 나중에 하나의 ARCHIVE-{KEY}.md만 읽어도 맥락을 복원할 수 있어야 합니다.
Improvement handoffarchive 이후 변경은 직접 수정이 아니라 /plan-improve로 시작합니다.

Failure Modes

  • pipeline이나 Dev 단계가 끝나지 않았으면 archive하지 않습니다.
  • 이동 대상 목록을 사용자가 확인하지 않으면 원본 이동을 진행하지 않습니다.
  • archive index나 backlog 갱신이 실패하면 bundle만 생성된 상태로 완료를 주장하지 않습니다.
