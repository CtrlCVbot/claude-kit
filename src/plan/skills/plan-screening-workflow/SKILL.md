## Overview

RICE 프레임워크 기반 아이디어 스크리닝 워크플로우를 정의합니다. 5개 평가 축으로 가중 점수를 산출하고, Go/Hold/Kill 판정 및 Lite/Standard 카테고리 판정을 수행합니다.

## Prerequisites

- 스크리닝 대상 아이디어가 `.plans/ideas/backlog.md`에 등록되어 있을 것
- 아이디어 상태가 `draft` 또는 `submitted`일 것

## Workflow Steps

1. **대상 선택**: 미스크리닝 아이디어 또는 재스크리닝 대상 식별
2. **5축 평가 수행**:
   - 비즈니스 가치 (30%): 매출 영향, 비용 절감, 경쟁 우위
   - 사용자 영향 (25%): 영향 사용자 수, 사용 빈도, 만족도 개선
   - 기술적 실현성 (20%): 기술 난이도, 의존성, 기존 인프라 활용도
   - 전략적 정렬 (15%): 제품 비전 적합성, 로드맵 정렬
   - 긴급도 (10%): 시장 타이밍, 규제 대응, 의존 관계
3. **가중 합산**: 0-100점 산출
4. **판정**:
   - Go (70+): 실행 승인
   - Hold (40-69): 보류 (조건 충족 시 재평가)
   - Kill (<40): 폐기
5. **Lite/Standard 판정**: 6개 트리거 기준으로 기획 깊이 결정
6. **결과 기록**: `screening-matrix.md` 업데이트

## 점수 체계

| 축 | 가중치 | 평가 기준 |
|---|---|---|
| 비즈니스 가치 | 30% | 매출/비용/경쟁 우위 |
| 사용자 영향 | 25% | 사용자 수/빈도/만족도 |
| 기술적 실현성 | 20% | 난이도/의존성/인프라 |
| 전략적 정렬 | 15% | 비전/로드맵 적합성 |
| 긴급도 | 10% | 타이밍/규제/의존관계 |

## Lite/Standard 트리거

Standard로 판정되는 6개 트리거 (하나라도 해당 시):
1. 3개 이상 화면 변경 필요
2. DB 스키마 변경 수반
3. 외부 API 연동 필요
4. 보안/인증 흐름 변경
5. 2개 이상 도메인 영향
6. 예상 구현 기간 1주 이상

## Output Format

- 스크리닝 결과: `.plans/ideas/screening-matrix.md`
- 판정: Go / Hold / Kill + 근거
- 카테고리: Lite / Standard
