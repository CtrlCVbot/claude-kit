## 설명

현재 `docs/user-guide-html`에 있는 정적 HTML 기반 사용자 가이드를 Next.js 기반 문서 웹사이트로 전환한다.

이 작업의 핵심은 `claude-kit` 사용자용 가이드를 웹사이트 형태로 제공하는 것이다. 동시에 이 전환 과정 자체를 `claude-kit`의 기획/개발 파이프라인 실행 예시로 문서화해, 사용자가 실제 산출물 흐름과 명령 사용 순서를 따라갈 수 있게 한다.

## 배경

현재 HTML 가이드는 기획 파이프라인, command 상세 페이지, lifecycle, reference 문서를 제공한다. 하지만 문서 페이지가 늘어나면 정적 HTML만으로 navigation, route 관리, 컴포넌트 재사용, 배포 검증을 유지하기 어렵다.

Next.js 문서 사이트로 전환하면 기존 HTML reference를 보존하면서도 sidebar, toc, Claude/Codex 탭, capability matrix, artifact flow 같은 문서 UI를 재사용 가능한 구조로 정리할 수 있다.

## 기대 효과

- 사용자용 `claude-kit` 가이드를 더 탐색하기 쉬운 웹사이트로 제공한다.
- 기획 파이프라인과 개발 파이프라인의 실제 사용 예시를 문서 안에서 함께 보여준다.
- Vercel Preview 기반으로 문서 사이트 배포 검증 흐름을 만들 수 있다.
- 기존 `docs/user-guide-html`은 migration reference로 보존하면서 Next.js 전환을 단계적으로 진행한다.

## 제약

- `claude-kit`의 command, agent, skill, hook, rule, installer 기능이 우선이다.
- 웹사이트는 부가적인 docs surface이며 core 기능 source가 아니다.
- `src/claude`, `src/codex`, `src/templates`, `scripts/setup.js`, `.claude`, `.agents`, `.codex`는 별도 승인 없이 수정하지 않는다.
- Vercel Production 배포는 즉시 목표가 아니며 Preview 검증을 먼저 목표로 한다.
- `/plan-design`과 `/plan-stitch`는 실제 사용 여부와 관계없이 checkpoint를 기록한다.

## 결정

`/plan-screen` 결과 `Go`로 판정하고, 사용자의 “권장 방향으로 질문 없이 진행” 지시에 따라 승인 상태로 이동했다. 이후 `EPIC-20260527-001` 아래에서 Feature 단위로 분리해 진행한다.
